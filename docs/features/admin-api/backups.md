# Backups

Making, keeping, scheduling, and restoring the site's [backups](../../running/backups.md). Every request here is under `/admin/api`, as the [admin's API](README.md) describes.

| Request | What it does |
|---|---|
| `GET backups` | The site's [backups](../../running/backups.md), with `site.backups`: `{"backups", "parts", "groups", "used", "free", "folder", "restoring", "schedule", "upload"}`. Each backup is `{"name", "file", "status", "kind", "created", "by", "note", "parts", "size", "reason", "job"}`, newest first: `status` is `running`, `done`, or `failed` (with its `reason`), `kind` is `manual`, `scheduled`, `before-restore`, or `uploaded`, `by` the display name of the account that made it (`null` from the command line), and `job` the job making it. Each part is `{"name", "group", "label", "description", "count", "bytes"}`, with what it holds now; `groups` are `{"key", "label"}` in order; `used` and `free` are bytes, `free` `null` when the host won't say |
| `POST backups` | Starts a backup of `{"parts", "note"}` as a job: `201` with `{"backup"}`. Run it with `POST jobs/{id}/run`. A `409` while one is being made; a `422` for no parts or one that isn't. Needs `site.backups` |
| `PATCH backups/{name}` | Changes a backup's `{"note"}` (up to 60 characters): `{"backup"}`. Needs `site.backups` |
| `DELETE backups/{name}` | Deletes a backup, `{"deleted": true}`, or cancels the one being made, `{"canceled": true}`. Needs `site.backups` |
| `POST backups/{name}/undelete` | Puts back a backup deleted in the last day: `{"backup"}`, or a `404`. Needs `site.backups` |
| `GET backups/{name}/download` | The backup's `.zip`, to save. Needs `site.backups` |
| `POST backups/upload` | Adds an [uploaded backup](../../running/backups.md), sent as the multipart field `file`: `201` with `{"backup"}`, its `kind` `uploaded`. A `.zip` without a `backup.json`, or holding a path a backup doesn't, is a `422`; one with the name of a kept backup a `409`. Nothing is kept either way. `GET backups` has `upload`: `{"limit"}`, the largest file the server takes in bytes, or `null`. Needs `site.backups` |
| `PUT backups/schedule` | Saves the [backup schedule](../../running/scheduled-backups.md), `{"frequency", "day", "hour", "keep", "parts", "notice", "to"}` (`frequency` is `off`, `daily`, or `weekly`; `parts` a list of part names or `null` for every part; `notice` is `failures`, `always`, or `never`; `to` an address or `""` for the site's), as the `backups.schedule` setting: `{"schedule"}`, as `GET backups` has it, with `next` (when it next runs, or `null`), `timezone`, `siteEmail`, and `canMail` (whether the site can send mail). A value that doesn't fit is a `422`. Needs `site.backups` |
| `POST backups/schedule/test` | Sends the schedule's test email, to `{"to"}` or whoever the schedule emails: `{"sent": true, "to"}`. A `422` when `to` isn't an address or the site can't send mail. Needs `site.backups` |
| `POST backups/schedule/preview` | An email the schedule would send, `{"stage"}` (`done` or `failed`) to `{"to"}`: `{"email": {"from", "to", "subject", "text"}}`. Needs `site.backups` |
| `POST backups/{name}/check` | What refuses restoring `{"parts"}` of a backup, and what it will do: `{"problems", "warnings"}`, each a list of sentences. Needs `site.backups` and `site.backups.restore` |
| `POST backups/{name}/restore` | Starts restoring `{"parts"}` of a backup as a job, the site's parts backed up first: `202` with `{"job"}`. Run it with `POST jobs/{id}/run`; when it's done, its `result` is `{"backup", "parts", "safety", "signedOut"}`, `safety` the backup made first (restore it to undo) and `signedOut` whether every session was ended. A `409` while a backup is being made or restored, a `422` for a problem `check` would name. `GET backups` has the restore running as `restoring`: `{"job", "backup", "parts"}`, or `null`. Needs `site.backups` and `site.backups.restore` |
