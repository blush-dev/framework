Toast

A chip that reports something that happened where you were not looking. A rule along its bottom edge counts it down, it stops while you read it, and where the action can be put back it carries an Undo.

Live

These fire real toasts into the host at the bottom right. Hover one, or Tab into its Undo, and the bar stops where it is — both the pointer and the keyboard hold it, and both have to let go before it resumes. Esc while focus is inside a toast dismisses that one.

A plain toast takes the place of the plain one standing, so routine reports do not pile up. A toast carrying Undo is not displaced by one — it stacks. Three at most; at the cap the oldest goes, which is the offer nearest to expiring anyway. Press Fill the stack and then Settings saved to see both halves of that.

The countdown

Frozen at four points, so the bar can be read as a picture. It is a 2px rule along the bottom edge in the kind's color, scaleX from 1 to 0 with its origin on the left, so the remaining width is the remaining time. The chip clips to its own radius, which is what curves the bar's ends without the bar having to know what --r-2 is.

Kinds

Four, and each changes the glyph as well as the color — status is never carried by color alone. info is for what a real build would do, which is not a thing that happened and should not wear a tick.

With an Undo

Everything that changes stored data and can be put back carries one, and lives ~7s rather than ~2.6s — the offer is only worth making if there is time to take it. A divider sits before it, as in the bulk bar. A toast that cannot promise a reverse does not offer one: Permalink copied has nothing to undo.

Markup

One chip. The bar is first so it paints under the content, and it is aria-hidden because the countdown is not information a screen reader needs — the message is, and that goes through the shared live region.

<div class="toast danger" role="group" style="--life:7000ms">
  <span class="toast-bar" aria-hidden="true"><i></i></span>
  <svg class="ic"><use href="#i-alert"/></svg>
  <span class="msg">Moved "Type on maps" to trash</span>
  <span class="div" aria-hidden="true"></span>
  <button class="undo" type="button">
    <svg class="ic"><use href="#i-undo"/></svg>Undo
  </button>
</div>

The host and the live region sit once at the end of the document:

<div class="toasts" id="toasts"></div>
<p class="sr" id="toastLive" role="status" aria-live="polite" aria-atomic="true"></p>

And the one call every screen makes. kind defaults to good; life defaults to 2600ms, or 7000ms when there is an undo:

toast(message, { kind, undo, life })

toast("Settings saved")
toast("Still used by 3 entries — remove it there first", { kind: "warn" })
toast('Moved "Type on maps" to trash', {
  kind: "danger",
  undo: () => { entryBack(was); afterEntries(); toast('Put "Type on maps" back'); }
})

The undo function restores exactly what the action changed and runs at most once — the offer goes with the toast, so nothing can apply the reverse twice.

Rules

  • The bottom rule is the countdown. A toast that disappears on a hidden timer is one people learn to read fast and then distrust; one whose bar is visibly draining can be ignored on purpose.
  • Constant width, constant rate. The bar is the same on a one-line and a two-line chip, so the same duration always feels the same.
  • The chip's border stays a border. 1px --border, as on every other overlay — the countdown is a separate line with a separate job.
  • Hover and focus pause it, and the holds are counted. A boolean took the second release as a release of both and restarted the clock, so every stray Tab bought the toast another few seconds.
  • The clock is a timer, not animationend. prefers-reduced-motion collapses every animation to nothing, and a toast hung off it would vanish on the frame it appeared.
  • Under reduced motion the bar stays whole and the toast still goes at its time. No motion, same behavior.
  • The message is set at --base, the theme's own body size — a toast is read at a glance by someone whose eye was elsewhere. The Undo beside it stays a notch down at 12.5px, where buttons sit everywhere else.
  • A plain toast does not displace one carrying Undo. It replaces the plain one standing instead — dropping an offer to make room for Settings saved takes away the only way back. At the cap of three the oldest still goes, because something has to.
  • An action reported but not performed cannot be undone. An Undo is a test of whether the action actually happened.
  • Esc takes the toast focus is inside, and nothing else. A toast is not an overlay the way the menus and the drawer are.
  • One shared role="status" region announces the message. A live region that gains a button is announced as a button arriving.
  • Past tense, sentence case, counts exact. Moved 3 posts to trash, never Posts trashed!
--surface--border--fg--accent --accent-soft--good-dot--warn-dot --danger-dot--shadow-2--r-1--r-2 --ctl-sm--s-2--s-3

No literal colors, radii or faces — the ring reads --r-2 for its corner and the kind's own -dot token for its stroke, so both admin themes and both schemes are had for nothing.

Why a bar, and not a full border

Settled, and recorded here so it is not re-opened. A full draining ring was the first version. Below, the rejected treatment and the shipping one, same duration, started on the same frame — which is the only way to see the thing that decided it.

Watch the ring crawl along the top, then snap down the right edge. The bar does not change pace.

Why that happens: a rounded rectangle's perimeter is not evenly distributed, so equal time is not equal distance. For the one-line chip above — 339 × 52 at --r-2 = 10px:

SegmentLengthShare of the countdown
Top edge319px41.7%
Right edge32px4.2%
Bottom edge319px41.7%
Left edge32px4.2%
Four corners62.8px8.2%

On a 2.6s toast the run spends about 1.1s on the top edge and crosses the whole right edge in 0.11s. And the shares move with the message: wrap it to two lines and the top drops to 39.6% while the sides rise to 6.5% each, so the same duration feels different depending on how long the sentence is.

What the ring had going for it

Distinctive — the whole object reads as timed, and the kind's color wraps the thing it describes. No extra element: the border is already there and is simply given a second job.

What settled it

Constant rate, identical on every chip whatever the message length. The chip keeps the ordinary overlay border — 1px --border, the same as a menu — so its edge never degrades as the time runs out. It is quieter: a danger toast stops being the loudest thing on screen for a routine trash. And it is the shape people already read as a timer.

The underlying fault

The ring makes one line do two jobs — this is the chip's edge and here is the time left — and they pull against each other. It is why the track had to move to --border-strong, which made the toast's edge heavier than every other overlay in the admin. The bar needs no such compromise.
