Tools

Tasks you run by hand, work done in the background, the log they write to, and copies of the site.

A backup is one .zip of what makes the site this site: its content, types, fields and relationships, its settings, redirects and jobs, and its people. Media is left out, because it is plain files you can copy like any others.Backups are kept on this server and hold password hashes, so download the ones that matter to somewhere private. They are never sent by email.

Backups: Sketch Notes

A fourth tab on Tools, beside Actions, Jobs and Logs. Everything here is the admin’s own pieces: page head, underlined tabs, a boxed notice, three stat tiles, a panel with a table, row menus, modals and toasts. Data is invented. The rules, numbered so they can be argued with:

  1. A backup is a file, and the screen says where it lives. One .zip, named by its date in mono, kept in a folder named by config. The intro says plainly that it is on this server and holds password hashes.
  2. Ten parts in three groups, each with its count and size. Content (entries, types, fields, relationships), Site (settings, redirects, jobs) and People (accounts, roles, sessions). Media is left out: it is plain files, copied like any others. The Holds column reads Everything, Everything but Sessions, or the first three with a count.
  3. Yours stay; the schedule’s rotate. Keep counts scheduled backups only. A backup someone made on purpose, with a note, is never removed by the schedule.
  4. Running is a row, not a toast or a spinner. Back Up Now puts a row at the top with a progress bar that names the step and the count. The row shows its own result, so finishing does not toast (§7).
  5. Failure says what happened to the site’s safety. A failed row names the cause and that nothing was kept, and Last Backup becomes the one attention tile, naming the newest good copy and whether an email went out.
  6. Restore makes a backup first, and that is what makes Undo honest. People parts start unticked. Accounts and Sessions each get their own warning, because restoring them changes who can sign in.
  7. Restore and Delete are apart. Download, Restore and Edit Note sit above a divider; Delete sits alone below it. Delete has Undo, because the file is only removed when the toast ends.
  8. Schedule is a form, not a set of switches. Its controls, the email ones included, are values saved together with Save Schedule; the panel reports Saved in place.
  9. None Yet hides the tiles. There is nothing to summarize, so the empty state takes the room and offers both ways forward.
  10. Email is a notice, never the backup. It goes to the site’s email unless another address is given, and it says what happened and links to this screen, which needs a sign-in. No attachment and no download link: a backup holds password hashes and sessions, and a link in an inbox works for whoever holds the inbox. The default is Only When a Backup Fails, plus one email when they work again, because a daily success email trains people to filter the one that matters. After Every Backup is one choice away. Only scheduled backups email; a backup someone starts by hand finishes on this screen.

Open

  • Default for email. The sketch defaults to failures only. The owner’s instinct was a notice either way; After Every Backup is drawn and costs one change of default.
  • When the site cannot send mail. The test button is the only way to find out today. Forms and the signed-out screens already ask where mail settings live and what happens when mail fails.
  • Encrypting the file. A passphrase set here would make a downloaded backup safe to store anywhere, at the cost of a passphrase someone must not lose.
  • Are sessions worth backing up? They matter only when moving to a new server; restoring them otherwise revives ended sign-ins. The sketch backs them up and restores them only when asked.
  • Tab or screen? Drawn as a fourth Tools tab. If restores grow a detail screen, Backups may earn its own panel item under Home.
  • Off-site copies. Sending each backup somewhere else is the obvious plugin hook. Not drawn.
  • Who may restore. Restoring accounts changes every person’s password. It probably needs its own capability.
